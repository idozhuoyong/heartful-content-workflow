# 小卓心享内容工作流

本工作流由单主 Agent 按文档执行，当前没有自动运行命令。运行字段和文件名以 [交接协议](../../docs/PORTABILITY_PROTOCOL.md) 为准；执行时同时读取 [领域规则](DOMAIN_RULES.md) 和 [公众号规则](WECHAT_RULES.md)。

## 前置条件与输入

执行环境必须能读写项目文件；涉及外部事实时还需联网核实或可信原始资料。输入接受主题、个人笔记、参考文章、目标读者、文体、篇幅和交付要求，不要求每天采集热点。

缺少低风险偏好时记录默认假设继续；涉及真实经历使用权限、账号定位或关键方向歧义时先确认，并继续整理不依赖答案的资料。不因缺少发布能力阻塞文字生产。

## 步骤与验收

| 步骤 | 行动与输出 | 完成条件 |
|---|---|---|
| `brief` | 保存 `input.json`、`state.json`、`decisions.md` | 范围、读者假设、文体与交付类型明确 |
| `topics` | 在 `topics.md` 记录候选与最终切口 | 单篇核心问题和内容增量明确，关键分歧已解决 |
| `research` | 保存 `sources.md` 与 `claims.md` | 重要外部主张可追溯；无外部引用时有明确说明 |
| `write` | 草稿保存至 `drafts/`，审核候选保存至 `articles/article-01.md` | 不含编造的作者经历；事实与观点边界清楚，符合文体与篇幅约束 |
| `visuals` | 保存 `image_manifest.md`，有素材时放入 `images/` | 文字交付的图片缺口明确；完整图文交付的素材及许可齐备 |
| `review` | 保存 `review.md`，修订后重新核对影响项 | 领域与公众号检查通过；不通过项不得伪装完成 |
| `deliver` | 保存 `delivery.md`，更新运行状态 | 清单对应实际文件和采用版本，交付类型准确，停在 `waiting_approval` |

每完成一步先落盘产物，再更新状态。正文写作中及时保存草稿；不把聊天中的正文当作唯一副本。完成正文不意味着图片、图文包或发布已完成。

## 失败与恢复

来源冲突或不足时，记录冲突并补证、缩小主张或排除；不能把推断升级为事实。无法获取参考全文时，不声称读过或模仿其具体内容。素材使用权不明时更换素材或列为缺口。

审核失败回到受影响步骤，记录原因和待重审范围；已有交付版本另存修订稿，不覆盖旧版。会话中断后按交接协议核对文件，从首个未完成步骤继续。

## 人工审批与交付边界

默认授权覆盖本地内容生产，交付后等待审核。若用户只要选题或方案，则止于相应范围，不自行扩展为完整文章。

保存平台草稿或正式发布须有对应平台、账号、文章版本和操作类型的明确授权。写入前核对当前能力并记录授权，写入后保留回执；未经确认的平台效果不算视觉验收通过。
